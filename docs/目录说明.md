# 目录与文件说明

本文档说明仓库当前各目录、文件的职责，以及武汉 spike 跑到初筛为止的数据流。产品目标与功能边界见 [PRD.md](./PRD.md)。

当前阶段：**广泛搜索 → 抽取 + 证据校验 → 高德 POI 匹配 → 初筛短名单**。精细搜索与打分尚未实现。

## 4. `src/alleyfinder/` 包代码

流水线脚本通过 `from alleyfinder...` 引用这里，避免把 API 细节写进每个脚本。

| 文件 | 作用 |
|---|---|
| `__init__.py` | 包入口。目前只有占位 `main()`（`pyproject.toml` 里的 `alleyfinder` 命令会调它）。 |
| `clients.py` | 三个外部 API 的封装。 |
| `prompts/__init__.py` | 提示词包标记，空文件。 |
| `prompts/extract.py` | 从网页摘要里抽餐馆的 system / user 提示词。 |

### `clients.py`

| 函数 | 作用 |
|---|---|
| `env(name)` | 读 `.env`；缺值直接报错。 |
| `chat(messages)` | 调 DeepSeek `deepseek-chat`，强制 JSON 对象输出。 |
| `search_web(query, count)` | 调博查网页搜索，返回 `title / url / summary / snippet / published_at`。 |
| `search_poi(keywords, city)` | 调高德 `place/text`，带 `citylimit=true`，返回 POI 的 id、标准名、地址、行政区、城市名、类型、坐标。无结果时抛错（`match_poi.py` 会捕获并记为未匹配）。 |

### `prompts/extract.py`

约束模型只输出 `{"shops": [...]}`。每条店铺含店名、地址线索、菜品、口碑词、广告/关店提示，以及必须能在原文中逐字找回的 `evidence`。禁止推测。

## 5. `scripts/` 流水线脚本

按运行顺序：

| 脚本 | 作用 | 输入 | 输出 |
|---|---|---|---|
| `api_test.py` | 连通性冒烟：各打一次博查 / DeepSeek / 高德，确认 key 和 url 可用。不写数据。 | `.env` | 终端通过/失败 |
| `spike_wuhan.py` | 武汉广泛搜索 + LLM 抽取 + 证据子串校验。 | 内置 5 条查询 | `mentions.jsonl`、`review.csv` |
| `match_poi.py` | 对去重后的店名做高德匹配，落到真实 POI。 | `mentions.jsonl` | `shops.jsonl` |
| `screen_shops.py` | 按 `poi_id` 合并提及，剔除一眼假的店，保留提及次数 Top 30。 | `mentions.jsonl` + `shops.jsonl` | `shortlist.jsonl`、`screen_dropped.jsonl` |

运行方式（仓库根目录）：

```powershell
uv run python scripts/api_test.py
uv run python scripts/spike_wuhan.py --extract-n 20
uv run python scripts/match_poi.py
uv run python scripts/screen_shops.py
```

`spike_wuhan.py` 的 `--extract-n` 控制送给模型的文档数，默认 20。

### 各脚本在做什么

**`api_test.py`**  
独立请求三个服务，不经过 `clients.py`。用来确认网络和密钥，而不是测业务逻辑。

**`spike_wuhan.py`**  
查询：`武汉 苍蝇馆子`、`武汉 热干面 老店`、`武汉 本地人 推荐 小吃`、`武汉 巷子 美食`、`武汉 开了十几年 餐馆`。按 URL 去重后取摘要，让模型抽店；店名和 evidence 规范化后必须出现在标题+摘要里，才标 `evidence_ok`。

**`match_poi.py`**  
店名规范化去重后逐个 `search_poi(name, "武汉")`，取第一条 POI。未匹配的只打印、不写入。请求间隔 0.2s，避免 QPS 超限。

**`screen_shops.py`**  
同一 `poi_id` 合并提及次数。剔除规则：城市名不含「武汉」、抽取店名与 POI 名对不上、证据/地址里出现商超词、店名带连锁痕迹、POI 类型为快餐等。按 `mention_count` 降序截取 30 家进入短名单。

## 6. `data/spike_wuhan/` 武汉 spike 产物

目录由脚本创建。被 `.gitignore` 忽略，换机器需重跑脚本生成。

| 文件 | 由谁写入 | 一行代表什么 |
|---|---|---|
| `mentions.jsonl` | `spike_wuhan.py` | 一篇网页里抽到的一次店铺提及（含 evidence、是否校验通过、原文 URL）。 |
| `review.csv` | `spike_wuhan.py` | 同上，表格版，方便 Excel / 表格里人工扫 `evidence_ok`。 |
| `shops.jsonl` | `match_poi.py` | 一个去重店名对应的高德 POI（标准名、地址、区、城市、类型、经纬度、`poi_id`）。 |
| `shortlist.jsonl` | `screen_shops.py` | 初筛通过的候选店，已按提及次数排序，最多 30 家。后续精细搜索从这里读。 |
| `screen_dropped.jsonl` | `screen_shops.py` | 初筛被剔除的店，带 `drop_reason`，用来检查规则是否过严/过松。 |

数据流向：

```
博查搜索摘要
    → mentions.jsonl / review.csv     （抽取 + 证据校验）
        → shops.jsonl                 （高德 POI）
            → shortlist.jsonl         （初筛留下）
            → screen_dropped.jsonl    （初筛丢掉）
```
